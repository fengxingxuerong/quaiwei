# 学术自检（`--academic-check`，v0.9.81）

> 类型：当前口径。改了 `src/engine/academic-check.ts` 就同步改这份。
> 一句话：论文/投稿这类稿子，用户要的不是"读起来更像人"，是**能不能投**。
> 这个模式把本仓已有的零件收成一个带退出码的判定。

## 1. 为什么单独一层

同一件"去 AI 味"的事，学术场景的失败方式完全不一样：

- 一般文章改坏了，读者自己看得出来；
- 论文改坏了，是"准确率 91.2% 变成 91.2 个百分点"、"`\cite{wang2024}` 没了"，**审稿时才炸**。

同类项目（`junbolian/Academic-Humanizer`，2026-10-19 建仓，一周 43★）卖的就是这个：
数字公式引用原样保留、缺证据打占位符、没清干净就明写 `NOT READY TO SUBMIT`。本仓零件都在
（数字/单位守卫、结构保真 23 条、逐条改动、残留痕迹地图），缺的是把它们收成一句判定。

## 2. 怎么用

```bash
# 单文件：不落盘，报告走 stdout，判定走 stderr + 退出码
ai-humanizer paper.md --academic-check

# 审别人改过的稿（LLM 深度模式产出 / 合作者版本）：引擎不参与改写
ai-humanizer paper.md --academic-check --against paper-rewritten.md

# 管道
cat paper.md | ai-humanizer --academic-check

# 显式指定文风（不给就默认 academic）
ai-humanizer paper.md --academic-check --style plain --intensity 0.4
```

网页版也有这个入口：专业视图工具栏里的**「学术自检」**按钮。有产出就审产出
（模拟"把别的模型改写稿粘进产出框"的场景），没有产出就先在本地按 academic 文风跑一遍再审。
面板自己不改稿，只列阻断项与提醒项（2026-10-26 浏览器实测，见 `evidence/mcp-smoke-2026-10-26.txt`）。
MCP 侧对应工具是 `academic_report`（参数 `text` + 可选 `rewritten`）。

**退出码**：

| 码 | 含义 |
|---|---|
| 0 | READY——机器没看见阻断项 |
| 2 | NOT READY——有阻断项，必须人看一眼 |
| 1 | 没法跑（输入缺失 / 为空 / 读失败） |

退出码 2 是给脚本用的：`ai-humanizer paper.md --academic-check \|\| echo "停一下，看报告"`。

## 3. 判什么、不判什么

**阻断项（判 blocked）**

| 项 | 判据 |
|---|---|
| 数字与单位 | `numericFidelityWarning()`：产出缺了原文的数字，或数字对但单位被改 |
| 结构 | `formatIssues()` 的 23 条不变式：代码块、表格、标题、引用块、缩进、结构行 |
| 引用键 | `\cite` / `\ref` / `\label` / `[@key]` / `[[EVIDENCE]]` 的键**丢了**或**凭空多了**（编造比丢更糟） |

**提醒项（只警告）**

| 项 | 判据 |
|---|---|
| 断言变重 | 产出里出现"显著/最优/首次/证明了/完全/必然/毫无疑问/彻底"，原文没有 |
| 残留痕迹 | `reviewText()` 数出来的套话残留 |
| 空查 | 全文没有引用键时明说"引用完整性这一项属于空查" |

**不判**：论证是否成立、结论是否过头、统计方法对不对。机器判不了，报告里明写这一句——
READY 不等于审稿人会收。

## 4. 实测：两种入口，响不响差很多

### 4.1 引擎自己的产出：很难被触发

2026-10-26 拿 10 类典型学术片段（含 `\cite`/`\ref`、上下标、全角数字、区间、单位、列表、公式）
× 3 种文风 × 2 档强度 × 3 个种子 = **180 组**跑下来，**阻断项 0 条**。

这说明两件事，都得说清：

1. 本地引擎的保真守卫（v0.9.75 → v0.9.79 那条线）确实守住了数字、引用与结构；
2. **这个门在引擎自己这条路上很少响**——它的价值是"以后改坏了会响"，不是"现在天天拦住你"。

### 4.2 外部改写稿（`--against`）：一抓一个准

同一篇原文，配一份"看起来还挺像"的外部改写稿（丢了引用键、数字写成"多个/明显"、表格被拆成一句话），
2026-10-26 实测：

```
ai-humanizer paper.md --academic-check --against bad.md
exit=2
✗ NOT READY：5 个阻断项（退出码 2）

- 产出缺少原文中的数字：4.2个百分点、91.2%
- 结构：表格分隔行不丢 —— 原文 1 条 → 产出 0 条
- 结构：表格行列数守恒 —— 表头+数据行 原文 2 → 产出 0
- 结构：表格行连续段守恒 —— 原文段长 [3] → 产出 []
- 引用键丢失（\cite）：wang2024
```

换一份只动措辞、数字与引用都留着的改写稿，同一条命令 `exit=0`。
**所以这条门的正确用法是审"别人改的稿"**——尤其是 LLM 深度模式的产出，那才是真正会动数字的路径。

## 5. 已知没做的

- **只跑本地引擎**：`--academic-check` 自己那条路不调 LLM。要看 LLM 深度模式的产出，
  用 `--against` 把产出稿喂进来（这也是推荐用法）。
- **不查数值一致性**：`毛利率 41.2%` 与文中其它数字的算术关系不检查（与数字守卫同一条边界）。
- **不校验论证**：方法是否合理、结论是否过头、统计选择对不对，机器判不了。
- **批量面板没接**：网页版的批量面板还没有学术自检；批量稿件请用 CLI。
- **不判人**：它判的是"改动"，不是"这篇论文该不该发"。
