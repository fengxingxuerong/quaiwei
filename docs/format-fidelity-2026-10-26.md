# 格式保真 · 从「形态正则」到「结构不变式」（v0.9.81）

> 执行时间：2026-10-26 01:00–03:40（GMT+8）
> 起点：v0.9.80（`3919dad`，全链绿） → 终点：v0.9.81
> 方法：按 `defect-taxonomy` 自己点名的「从未修过的类别」开工 → 先建判据（带反向对照）
> → 拿真实语料跑批 → **人眼读样本** → 修根因 → 补测试 → 再跑全链。

## 一、为什么挑这一类

`npm test` 输出里那张覆盖度盘点表把话说得很直白：

```
格式损坏   层=切分层   签名 4 条   修复 0 次
内容失真   层=外部不可修 签名 2 条   修复 0 次
从未修过的类别（体检优先方向）2 个：格式损坏、内容失真
```

但「修复 0 次」这句其实**不准**——v0.9.54~v0.9.65 明明修过一大批（围栏冻结、表格保分隔符、
缩进块、裸代码行、整篇清理挖代码……）。问题出在**记账**：那批修复当时只落在代码与单测里，
没人回填对照表，于是索引开始说谎。**这本身就是本轮第一个发现**。

真正没被覆盖的是**判据形态**：`scan-bugs.ts` 那 4 条签名都是**形态正则**
（`/(https[：，]|12[：，]30)/` 之类），它找的是「出现了某个坏形态」；
而格式损坏的主形态是「**结构被拆了**」——少了字符、空行插错位置、行被粘连。
正则天生看不见「少了东西」。所以本轮的动作是换判据，不是再加一条正则。

## 二、判据：23 条结构不变式（`src/engine/format-integrity.ts`）

| 组 | 判据 |
|---|---|
| 逐字保留 | 围栏块、行内代码、frontmatter、缩进块 |
| 目标守恒 | 链接目标/引用定义/自动链接、URL、邮箱、时间、日期、HTML 标签 |
| 行结构 | 标题层级序列、setext 下划线贴住标题、任务清单勾选框、结构行的续行 |
| 连续段 | 表格行、列表项、引用行、行首标记、缩进行（**连续段长度必须守恒**） |
| 表格 | 分隔行不丢、行列数守恒、列数（竖线数）守恒 |
| 其他 | 强调标记 `**` 成对数量守恒 |

判据纪律（每条都是本项目踩出来的）：

1. **判结构是否还有效，不判字节是否相等**——表格单元格里的中文**应该**被改写。
2. **先锚定原文，再看产出**：第一版按「产出里第 i 与 i+2 行都是同类 → 中间不许空行」判，
   扫出 **60 处假阳性**——有序列表与紧随其后的无序列表**原文就隔着空行**（本就是两张列表）。
   改成「原文连续段长度 == 产出连续段长度」后归零。
3. **散文软换行不算损坏**：`humanize()` 对普通正文的既定口径是「一行一段」，
   把软换行判成损坏会与设计打架；只有**锚在结构行上**的续行被拆开才算缺陷。
4. **每条判据都要能被反向对照触发**：`--selftest` 把 23 条判据逐条喂一份**故意弄坏**的产出，
   不响就是永真式，直接红。（`fidelity-guard.test.ts` 的教训：三次「探针自己有 bug 却被当成引擎缺陷」。）

本轮探针自己又被抓出两次假阳性（已修，记在这里防复发）：

- `[^1]: 脚注定义` 被引用式链接定义的判据吃成了「链接目标」，于是报「链接目标丢失」；
- 表格/列表的「插空行」判据没锚定原文（见上第 2 条）。

## 三、实测：用户路径干净，机械扰动入口没有盾

复现：`npx tsx scripts/format-fidelity-sweep.ts`（**17 段格式密集语料 × 4 档 × 30 种子 × 2 管线 = 4080 次运行**）

| 管线 | 结果 |
|---|---|
| `humanize()`（产品路径：Web/桌面端、CLI、DSH 插件） | **0 处结构违规** |
| `mechanicalShuffle()`（机械扰动公开入口） | **3543 处** |

`humanize()` 这一侧全绿不是走运：语料里专门塞了对抗性形态（setext 下划线、任务清单、
两空格续行、`~~~` 与四反引号围栏、未闭合围栏、围栏里的嵌套围栏、引用里的表格与围栏、
转义竖线 `\|`、autolink、参考式链接、HTML 块与注释），v0.9.54~v0.9.65 那批保护都接住了。

## 四、两个真缺陷（都在用户路径，**默认档 0.3 就中招**）

### ① setext 下划线被插空行拆开

```
标题一⏎===          →  标题一⏎⏎===        （标题不再是标题）
```

而且不止于此：下划线离开标题行之后，下游结构层的 `splitSentences + join("")`
会把 `===` **直接粘到标题尾巴上**（`标题一===`）——形态比空行更糟。

根因：段落层 `text.split(/\n+/)` 把每一行当独立段落、`join("\n\n")` 统一拉成双换行，
而「下划线要贴住标题」这条**分隔符语义**当时没有任何判据。

### ② 结构行的续行被拉成独立段落、缩进被 trim

```
- 第一项，后面跟一行没有标记的续行      - 第一项，后面跟一行没有标记的续行
  续行内容与上一行同属一个列表项。  →   ⏎
- 第二项                                续行内容与上一行同属一个列表项。⏎
                                        - 第二项
```

Markdown 语义变了：原文是一个紧凑列表项段落，产出变成松散列表（续行成了独立段落）。

### 修法

`text-shield.ts` 加三个判据（`isContinuationLine` / `isSetextUnderline` / `isSetextBlock`），
`humanize.ts` 段落层：

- 分隔符：冻结/结构行相邻（原有）+ **结构行与它的续行相邻**（新增）+ **setext 下划线贴住标题**（新增）
  → 一律沿用**原文分隔符**；
- 缩进：结构行的续行，行首空格原样贴回（v0.9.65 给嵌套列表项修过同一个坑）；
- `isProtectedBlock` 纳入 `isSetextBlock`，让含下划线的段整段跳过下游各层。

### 一次自我否定（差点改过头）

第一版判据是「上一行也是续行 ⇒ 就当结构续行」。12 样本棘轮**当场变红**：

```
❌ E/N1 基线 4.8，当前均值 1.2   ← 引擎产物分数掉了 3.6 分（看着像"变好"，其实是整篇被粘成一段）
```

N0 叙事稿正是「**每段缩进两格、段间没有空行**」的中文粘贴稿——那种稿子的既定口径就是一行一段。
第一版会把整篇粘成一个大段，把该分的段全吃掉。

于是判据改成**锚定制**：续行必须**往回穿过连续的续行**，落在**结构行**上才算数
（`humanize.ts` 的 `structFamily` / 探针侧的 `anchoredToStruct`，两侧同源）。
改完 N1 的 E 值回到 **4.8**（与改动前逐位相同），12 样本棘轮全绿。

> 教训：这类"顺手扩大判据"的改动，端到端棘轮比单测先看见问题——单测只钉了形态，棘轮钉的是分数。

## 五、已知边界：`mechanicalShuffle()` 没有格式盾（**登记，不在本轮修**）

实测 3543 处，六类结构破坏：

| 判据 | 最小复现（i0.3 默认档） |
|---|---|
| 表格分隔行/连续段 | `\| 模块 \| 改动 \|` ⏎ `\| --- \| --- \|` → 三行被粘成一行 |
| 围栏块逐字 | 块内被插入空行 ⇒ 闭合围栏错位 |
| frontmatter 逐字 | `---⏎title: X⏎---` → `---title: X---`（换行被吃） |
| 缩进块逐字 | 四空格缩进被 trim，块身份丢失 |
| 标题层级序列 | 标题与注入语气锚粘连、被合并 |
| 结构行的续行 | 续行被拆成独立段落 |

**根因定位**（`artifacts/_fmt-pinpoint.ts` 逐步骤复跑编排，看第一个破坏结构的步骤）：

```
① i0.3：boostBurstiness(w, …)            TTT_LL → T_LL
② i0.6：structuralShuffleParagraph(p)    TTT_LL → T_LL
③ i0.6：boostBurstinessIfLow(w, …)       L → L 粘连 + 语气锚"嗯。诶。咳。"注入正文
```

三步是同一个机制：**`splitSentences + join("")`** 在「不是段落的东西」上跑，把行内换行吃掉；
而 `humanize()` 恰好用 `isProtectedBlock` + 保原文分隔符把这三步挡住了
（v0.9.54~v0.9.65 那一批），`orchestrator.ts` 从头到尾**没有查过任何一次盾**：

```ts
// src/engine/shuffle/orchestrator.ts:99（现状）
working = working.split(/\n\n+/).map((p) => structuralShuffleParagraph(p, …)).join("\n\n");
```

**为什么本轮不改**：这个入口**没接任何已发布路径**——CLI（`scripts/humanize-cli.ts`）、
`index.js`、`.dsh/` 里都没有调用点，UI 也不调它，改它等于重写一层编排（还要连带
`varyParagraphs` / `resegmentParagraphsAggressive` / `boostBurstiness` 全族）去换一个
用户摸不到的收益，风险与收益不匹配。

**下次要改的话，入口是**：照 `humanize()` 那套（`splitParagraphChunks` 逐行切 + `frozen`/`mdStruct`
判定 + 保原文分隔符 + 下游各层 `isProtectedBlock` 闸门），而不是在末尾打补丁。
探针已经把它长期盯住了（见下节），改完会立刻转绿。

## 六、门禁与记账

- 判据本体：`src/engine/format-integrity.ts`（23 条 + 语料 + 反向对照自检）；
- 单元门禁：`src/engine/format-integrity.test.ts`（永真式自检 + 17 语料 × 4 档 × 5 种子 + 两个缺陷专向用例）；
- 批量实验：`npm run sweep:format`（**已进 `check:release` 链**，全量 2.8 秒）；
  退出码只由 `humanize()` 决定——机械扰动入口的命中**只报告**，不让它把门禁染红；
- `defect-taxonomy`：格式损坏 `fixes` 从 0 → 9 条（含 v0.9.54~65 那批补登记 + 本轮 2 条），
  签名登记 4 → 27 条（新增 `format:*` 结构不变式族）；
- 「内容失真」按纪律**保持 `fixes: []`**（只检出、不能修，改它就是编造原文），
  但在 `desc` 里补上了 v0.9.75~v0.9.79 的检出线与 `npm run sweep:fidelity`；
- 本轮没有改 `内容失真` 的引擎行为——它已由数字/单位保真守卫与批量实验覆盖，
  本轮只是把这条线的存在**写进对照表**，避免下一个人再按「修复 0 次」去重做一遍。
