# 数字保真这条线：从一次真实丢数据，到三道检查（2026-10-25）

> **类型：证据**（判据设计的过程记录；结论部分已落在代码里，这里讲**为什么长这样**）
> 涉及版本：v0.9.75 → v0.9.76 → v0.9.77
> 复现工具：`npm run sweep:fidelity` · `npm run compare:models`

## 一、起因：一次真实的整句丢失

2026-10-25 做「3 体裁 × 5 模型 × 2 轮」对比时，矩阵里跑出这样一对：

```
案例  C14-finance-flash（财经快讯）
模型  deepseek-v4-flash · 第 2 轮
原文  报告期末，公司总资产达到 126.75 亿元，较上年末上升 6.3%，资产负债率维持在 41.2% 的较低水平。
产出  （整句消失）资产负债率维持在 41.2% 的较低水平。
```

`126.75` 与 `6.3%` 随句子一起没了，其余 10 个数字都在。
**这不是"写错数字"，是"把带数字的句子删掉"**——反方向的失真（编造是多出断言，这是少了事实）。

为什么以前没被发现：当时走的 CLI `--api --no-deep`（单轮改写），没有深度模式的收稿终审与编造复核。

## 二、判据怎么定的：只查「数量型」事实

第一版（v0.9.75）把**所有**数字都当事实，结果被自己的扫查工具打回来：

| 报告 | 原文实际 | 结论 |
|---|---|---|
| C4 丢「200」 | 型号 **X200 智能会议终端** | 我把型号当数量了 |
| C12 丢「3」 | 「3 个指标」→ 模型写「三个指标」 | 中文数字的合法改写 |

v0.9.76 收窄成 `quantitativeFacts`，两刀切掉假阳性：

```
✗ 单个数字 1~9       「3 个」↔「三个」是最常见的合法改写
✗ 紧跟 ASCII 字母     X200 / iPhone15 / 5G / Wi-Fi 7 是标识符
✓ 多位数 / 小数 / 百分数 / 带单位量     真正的数据都在这类
```

**为什么宁可漏报**：这条提示出现在 CLI 输出与界面 note 里。一次误报，用户就会学会忽略它——
那比没有提示更糟。所以口径刻意保守，并在代码注释里写明"只查数字、不查实体"
（中文实体的同义改写边界太模糊，误报率压不住）。

## 三、三次自我否定

这条线值得记的不是"我们加了检查"，而是**三次检查被自己的工具推翻**：

| 版本 | 谁推翻了谁 | 结果 |
|---|---|---|
| 0.9.75 | 真实缺陷推翻了"LLM 不会丢数字"的假设 | 加守卫 |
| 0.9.76 | **扫查工具推翻了守卫**（X200 / 三个指标） | 收窄口径；回放 24 次假阳性 3→0、29 次真命中仍 1 |
| 0.9.77 | **测试推翻了我们的判断**（以为深度模式没数字检查） | 实际 QC 早有；只补回译洗稿与严格保真的归因 |

0.9.77 那次尤其值得记：我上一版结尾写「深度模式没有数字检查」，写用例时直接被打脸——

```
Error: 各轮质检均未通过（数字 126.75 出现次数减少（1→0）），已回退本地引擎
```

用例因此改成断言**真实契约**（非严格模式同样不交付丢数字的稿），而不是我原先猜的"交付 + 提示"。

## 四、现在哪条路径有什么检查

| 路径 | 检查 | 丢数字时的行为 |
|---|---|---|
| 本地引擎 | 无（不调模型，不存在丢失） | — |
| **单轮 LLM**（`--no-deep`） | `numericFidelityWarning`（v0.9.75） | 默认写 note；`--strict` 整稿回退本地 |
| **深度模式** · 候选期 | 本地质检「数字出现次数减少」 | 该候选被否，轮次重来 |
| **深度模式** · 收稿出口 | `deliver()` 数字检查（v0.9.77） | 兜住**回译洗稿**引入的丢失；`--strict` 抛否决 |
| 批量面板 / CLI 报告 | 同单轮/深度，warning 进 note 与 `--report` | — |

## 五、复现方式

```bash
# 5 篇数字密集语料 × 5 模型批量扫查（发现丢失即退出码 1）
npm run sweep:fidelity

# 3 体裁 × 5 模型 × N 轮，看客观指标与两两差异
npm run compare:models -- --src docs/某稿.txt --runs 2
```

两个工具都**不打印 Key**（只打后缀 4 位），Key 来源：`SENSENOVA_KEYS` → `scripts/.sensenova-keys`。

## 六、已知局限（写在最前面，免得被当成"事实全保真"）

1. **只查数字**：人名、机构名、时间跨度、因果关系的篡改抓不到；
2. **中文数字不查**：`3 个` → `三个` 视为等价；反过来 `三千万` → `3000 万` 也可能漏；
3. **单位不计**：`126.75 亿元` 变成 `126.75 万元` 目前只查数字本身——单位错误抓不到（下一步值得补）；
4. **不校验数值一致性**：`毛利率 41.2%` 与文中其它数字的算术关系不检查。

第 3 条是这条线最明显的下一步：数字对了、单位错了，一样是事故。
