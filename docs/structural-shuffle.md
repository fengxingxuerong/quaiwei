# 受限句序重排（`--structural`，v0.9.82）

> 类型：当前口径。改了 `src/engine/structural-shuffle.ts` 就同步改这份。
> 一句话：在**不新增任何内容**的前提下，把段落里的相邻两句换个位置——只换一次，只换守卫全过的。

## 1. 为什么做这个（以及为什么只能这么做）

SCORECARD「不能做什么」第 2/9 条长期写着：本地引擎"换词不换骨"，句序与段序不动。
这是"不新增事实"的代价——竞品 sgaofen 用 12B 权重做到了结构级重写，代价是 4GB 权重
和中文 73% 的事实保真。

本模块给出中间路线：**产出是原句的一个排列**，句的多重集逐字不变。没有新句子、没有新词、
没有新数字，"不新增事实"在构造上成立，不需要靠事后校验去兜。

代价是能力有限：只交换**相邻**两句、每段至多一次，不重切段落、不打散总分总。
自由的结构级重写仍然要走 LLM 深度模式（`--api`）。

## 2. 怎么用

```bash
# 默认关；要开就显式给
ai-humanizer ./稿子 --out ./out --intensity 0.7 --structural

# MCP
{ "name": "humanize_text", "arguments": { "text": "...", "structural": true } }
```

网页版在**专业视图**的开关条上：「🔄 句序重排」（默认关，与 CLI / MCP 同一个开关）。

生效需要同时满足三个门，缺一不动：

| 门 | 判据 | 谁在管 |
|---|---|---|
| 强度 | `intensity ≥ 0.55` | `humanize.ts` 结构层 |
| 体裁 | 论说 / 公文 / 学术 | 同上（叙事、人写沿用"保留作者结构"的既有裁决） |
| 段落 | 非冻结块、非事实密集段、非标题行、非剧本【场景】行 | 本模块段级防线 |

**默认关时产出与 v0.9.81 逐字相同**——那段代码一行都不执行，`structural-shuffle.test.ts`
有一条用例专门锁这个。

### 2.1 概率门控：开了不等于必然换

三道门全过之后还有一次概率抽样。30 种子实测 **14/30 触发交换**，
分档大致 0.7 档 45% / 1.0 档 78%。守卫没放行或没抽中时，产出与默认路径**逐字相同**。

⇒ 「开了 `--structural` 却看不出变化」是设计内行为，不是功能坏了。
CLI / MCP 默认固定 seed（20260905），同输入同产出可复现；**网页版每次随机挑种子**，
同一篇稿可能这次换、下次不换，提示里会报出中选种子可回填复现。

（v0.9.84 之前这条只写在内部记录里，容易被读成失效，故在此明示；语义已发版，不改行为。）

## 3. 五类守卫（每条都对应一次真实翻车模式）

交换相邻句最大的风险不是改内容，是**改坏指代与逻辑顺序**：

| 守卫 | 拦住什么 | 不拦的后果 |
|---|---|---|
| 回指开头 | 后句以「他/她/它/这/那/此/其/该/其中/为此/据此」起头 | 指代悬空，读者不知道"这"指谁 |
| 序列与因果开头 | 「首先/其次/最后/因此/但是/总之/换句话说…」 | 直接摧毁作者的论证骨架 |
| 引语语境 | 句内出现任何引号字形（`「『」』""`） | 说话人锚定在句序上，交换即张冠李戴 |
| 跨句数字引用 | 句内含数字/百分比/「第 X」 | 「总计 12 项。其中 5 项…」交换后算术语境断裂 |
| 首句锚定 | 段落第一句永远不动（交换从 `i ≥ 1` 开始） | 定场句被挪走，整段失去话题 |

另外两条结构性约束：**句长 < 8 字不参与**（碎片化语境里短句多是承接/语气成分）、
**每段至多换一处**（最小干预，多换只放大风险）。

## 4. 验法

```bash
# 单测（守卫、句多重集不变、默认关逐字相同）
npx vitest run src/engine/structural-shuffle.test.ts

# 真实产出对比：同一 seed 开关前后
npx tsx scripts/humanize-cli.ts in.txt --intensity 0.7 --seed 42
npx tsx scripts/humanize-cli.ts in.txt --intensity 0.7 --seed 42 --structural
```

实测样例（2026-11-04，一篇论说稿）：开启后首句「数字化转型已经成为…必然趋势」被换到第三句，
句多重集未变、代理分未变（65→42 与不开时一致）。**分数不变是预期的**——aiScore 对句序是盲区，
这也正是它不能当唯一指标的原因（见 `register-metrics.md`）。

## 5. 已知边界（别在外面替它夸口）

1. **守卫放行 ≠ 读着顺。** 句序合法但语感生硬是可能的（尤其首句定义句被后移时）。
   所以默认关，且建议拿真实稿件人工过一眼再决定是否常开。
2. 只动**相邻**句。跨段、跨三句以上的重排都不在范围内。
3. 事实密集段（数字多、专名多）整段跳过——判据与结构层同口径，见 `text-shield.ts`。
4. 与任何检测器官方分无标定关系。它的价值是"端到端多走一步"，不是"分数更好看"。
