# 桌面端冒烟测试：两个环境坑与一份可执行的判据（2026-10-23）

## 0. 一句话

`verify-pruned` 只验「模块可加载」，不验「窗口能不能起来」；而用户最容易遇到的失败形态
恰恰是「双击没反应」。为此补了 `scripts/smoke-desktop.mjs`，并把两次踩到的环境坑记在这里——
**两次都不是包的问题，是环境**。

## 1. verify 的边界（为什么还要冒烟）

`electron-app/verify-pruned.cjs` 验三件事：

| 项 | 内容 |
|---|---|
| 必须保留项 | 关键文件在不在、绝对路径能不能解析 `@huggingface/transformers` |
| 随包文档与版本 | `使用说明.txt` 与源一致、`resources/app/package.json` 与仓库同版本 |
| 新鲜度 | 产物指纹是否来自当前源码 |

它**不跑**：主进程有没有崩、窗口有没有出现、PPL 首次下载（~99MB）会不会失败。
前两项正是「双击没反应」的典型表现。

## 2. 用法

```bash
node scripts/smoke-desktop.mjs            # 默认 10 秒观察窗
node scripts/smoke-desktop.mjs --wait 20  # 启动慢的机器放宽
```

判据只有一条：**启动后存活到观察窗后半程 ⇒ 过**；提前退出 ⇒ 不过（退出码 1，并打印排查顺序）。
脚本会先跑一次 `QuAiWei.exe --version` 自证环境（见坑一），然后 detached + `stdio: ignore` 启动，
结束时只杀自己起的那棵树。

## 3. 坑一：`ELECTRON_RUN_AS_NODE=1`

**现象**：`QuAiWei.exe` 启动即退，或命令行下卡住不动；`QuAiWei.exe --version` 打印的是
`v24.22.0`（Node 版本），而不是 Electron 的 `v43.8.0`。

**根因**：父进程本身是 Electron 应用时（Agent 宿主、某些 IDE、某些终端集成），环境里常带着
`ELECTRON_RUN_AS_NODE=1`。子进程继承后，Electron 会**退化成普通 Node**：

- 带参数 → 当成 node 的 CLI 参数，`--enable-logging=stderr` 会报 `bad option`；
- 不带参数 → 进 REPL，读 stdin 卡住（2026-10-23 实测：一次 180 秒超时就是这么来的）。

**判定**：`--version` 的版本号是最省事的判别器——Electron 43.x 打 `v43.x`，Node 打 `v24.x`。
`smoke-desktop.mjs` 每次启动前都会验一遍并打印结论。

**处置**：启动前把该变量从**子进程**环境里删掉（不要只在自己 shell 里 `unset` 后就用
`Start-Process`——某些宿主会重新注入）。脚本里的 `cleanEnv()` 就是干这个的。

## 4. 坑二：没有交互桌面的会话

**现象**：干净环境下 `QuAiWei.exe` 仍然启动即退，退出码 `2147483651`（`0x80000003`,
`STATUS_BREAKPOINT`）——这是 Chromium 初始化失败时的 `CHECK` 行为，不是崩溃转储。

**判据（关键）**：换一个已知能跑的 GUI 程序对照。2026-10-23 实测：

```
Start-Process notepad.exe → hasExited=True，exitCode=0，没有窗口
```

连记事本都起不来 ⇒ 该会话没有交互式 window station（Agent 宿主、CI 服务、Session 0 等）。
这种情况下**不要怀疑产物**，换到用户自己的桌面终端再跑。

**推论**：CI 里只能跑到 `verify` + 产物自检；GUI 冒烟必须在真机上做，不能写成 CI 门禁。

## 5. 真机冒烟清单（人肉 5 步，约 2 分钟）

1. 解压**整个** zip（不要只把 `QuAiWei.exe` 拖出来——它依赖同目录的 dll 与 `resources/`）
2. 双击 `QuAiWei.exe`：窗口出现，标题「趣AI味 · QuAiWei」
3. 粘一段 AI 风格的中文 → 点「去味」→ 有输出、有前后评分
4. 设置里点一次「PPL」：首次会下 ~99MB 的 `bert-base-chinese`，下完能出分（**首次联网**是唯一一次）
5. 关窗再开：上一步的配置与历史还在（桌面版走 `safeStorage`，不是 localStorage）

## 6. 起不来时的排查顺序

1. **先看 `--version`**：打 Node 版本 ⇒ 坑一，别往下查
2. **事件查看器 → Windows 日志 → 应用程序**：找 `QuAiWei.exe` 的 `Application Error`，
   看 faulting module（缺 VC++ 运行库常在 `VCRUNTIME140.dll` 或 `vcruntime`）
3. **安全软件 / SmartScreen**：未签名的 200MB exe 被拦是常态，加白名单后重试
4. **产物完整性**：`cd electron-app && npm run verify`（会逐项报缺什么）；缺文件就 `repack`
5. 以上都正常再怀疑代码——按目前 20+ 个版本的记录，这一步几乎没轮到过
