## 3. 该对齐的（按性价比排）

### 3.1 占包名 + MCP server —— 捡起来就赚

- **[事实]** npm registry 查 `ai-humanizer`、`quaiwei`、`@fengxingxuerong/quaiwei` 全是 **404**，没人占；
  而 `ai-humanizer` 正是本仓 `package.json` 的 `name`。
- **[事实]** 本仓 `SKILL.md` 的调用方式是 `npx tsx scripts/humanize-cli.ts`，要求仓库在本地 + Node ≥22.12；
  同类 skill 用 `npx skills add <repo>` 一步装完。装完 skill 但引擎不在手上的断链风险，没人替你兜。
- **动作**：发布到 npm（`bin` 已有 `dist-cli/humanize-cli.mjs`，`files` 也已列）。再写一个 stdio MCP server，
  暴露 `humanize_text` / `detect_ai` / `quality_report` 三个工具。
  本周 humanizer-ru（MCP + Chrome 扩展）与 humanpen-mcp 都在做这件事，它是这周唯一被反复承认的新入口。

### 3.2 中文地区变体 —— 确定性词表的主场

- **[事实]** 繁中侧还在长：speak-human-tw 1,077★（38 痕迹 + 两岸用词 + 半形标点）；
  acchuang/zh-tw-humanizer（60 特征 + 157 组两岸用词 + `--source` 保真检查）；nagameTW/formosa-humanizer。
- **[推断]** LLM 做地区变体会漂（同一句两次给不同答案），词表做则确定、可复现、可测试——
  这是本地引擎相对 skill 竞品的唯一结构性优势。
- **最小动作**：`--variant zh-TW` + 两岸用词表 + 半形/全形标点规则 + 30 句对照测试。不走 LLM。

### 3.3 把账本变成对外成绩页

- **[事实]** "凭证覆盖率 0/18""6/18 点 x 轴漂移"这些现在只写在 README 的警告区，是内部口径；
  竞品对外一律自报（"95% 通过""16/16 盲测"）。
- **动作**：一页可点开的成绩页——能做什么 / 不能做什么 / 怎么复现（`npm run test:calib` 等）/ 已知失败 5 条。
  零新增测量成本，全部复用现有门禁产出。

### 3.4 学术线单独包一层

- **[事实]** junbolian/Academic-Humanizer 建仓 7 天 43★，卖点是"每个数字、公式、引用原样保留 + 硬出口"；
  matsuikentaro1/humanizer_academic 287★。
- **[事实]** 本仓已有数字/单位守卫（v0.9.75→v0.9.79）、格式保真 23 条结构不变式（10-26）。
- **[推断]** 缺的不是能力，是"论文 / 投稿"这个场景的报告长相。当前 README 的话术是"降 AI 率 / 送检"，
  这恰好是学术人群最容易被判违规的说法——同一套能力换个入口包装，风险更低。

### 3.5 原地改 .docx —— 排期，不急

humanpen-mcp 的路子是"按检测报告定位段落 + 原地改 + 保表格/公式/图片/引用"。
本仓 docx 现在是纯文本往返，样式会掉；format-integrity 已经在量这件事，改成原地编辑是后一步。

### 3.6 进索引榜 —— 半天

agentskillshub / awesome-humanizer-skills 是现成的分发渠道，248 个 repo 的索引有人读。
**[事实]** 本仓不在榜上（全表搜 `quaiwei` 只搜到 `LifelongLazyLearner/qu-ai-wei`，没有 `fengxingxuerong`）。

## 4. 不该对齐的

- **bypass 工程**：Turnitout 的"剥 C2PA 元数据 / 清零宽字符 / 打掉 token 追踪"，以及"95% 过 Turnitin"。
  跟了就等于把 README 顶上的诚实声明自己推翻，并且与学术人群的风控正面冲突。
  （零宽字符清洗作为"粘贴卫生"可以做，别包装成"去除追踪"。）
- **翻译链**：lynote 的 中→日→芬兰→英 四条腿。它靠意义漂移换结构变化，与本仓"不篡改原文内容"的实测结论直接冲突。
- **再写更长的词表**：本周五个新中文 skill 都在做这件事。继续堆不产生新的评测证据。
