### 1.4 网关恢复后的执行协议

1. **语料固定**：同一批 `cases.json` 23 篇原文，禁止各家用各自样例；长度分层另立子面板。
2. **产臂**：本仓用上面的固定 seed；竞品产物必须**真跑出来**，留 raw 文件 + 完整命令 + 版本 + 时间戳。
   每篇经 `prepare.mjs` 校验，缺篇即停。
3. **改稿参数对齐**：强度/档位取各家「推荐档」并记录，不为了赢专门调本仓参数；调了就单独标注。
4. **裁决**：
   `python scripts/eval-dual/ab_accept.py --arm-a <quaiwei> --arm-b <competitor> --seats AB --model-a <异源> --model-b <异源>`。
   双席反序 + 配对强制选择（「哪段更像 AI」），不用绝对分。
5. **判据**：报 B 胜率、双席一致率、甲被选率、二项 p。
   `p ≥ 0.05` 一律写「**测不出差异**」，不得写成赢或输；
   历史四次单点改动 A/B 全落在 0.43–0.52，差异过小时双席一致率会塌到 0.348。
6. **同时量保真**：逐篇 diff + 数字守卫 + 结构不变式，防止「更像人但改错数」赢。
7. **归档**：`evidence/eval-cross-<date>/`（raw / arms / manifest / JSONL / 报告），
   结论连同版本、网关、模型、日期一起引用；跨批次复测后才可对外。

## 2. #5 docx 富文本原地编辑

### 2.1 现状与对手

| | 现状 | 对手 |
|---|---|---|
| .docx | 零依赖 OOXML 解析，**只取段落纯文本**；输出重建 docx，样式/批注/修订/图片/公式全掉（[SCORECARD](../SCORECARD.md) §2 第 7 条） | HumanPen：.docx/.pptx 原地改，保表格/图片/引用/公式，可按 Turnitin 报告定位段落；sgaofen app 0.3.2 支持 docx/PDF 导入、CLI 保 headings/tables/code |
| .pptx / .pdf | 不支持 | HumanPen 支持 pptx；商业 SaaS 支持 pdf 上传 |

### 2.2 方案（不动引擎，加一层 XML 往返）

1. 解包 docx zip，**只改 `word/document.xml` 的 `<w:t>` 文本节点**；其余 ZIP 条目逐字节回写。
2. **不可改区域**：`<w:instrText>`（域代码）、OMML 公式、脚注/尾注、批注引用、
   文本框、`<w:br>` / `<w:tab>`、超链接关系、`w:rPr`（run 属性）一律不动。
3. **改写单位 = 段落**：同段 `<w:t>` 拼接 → `humanize()` → 回写；**不跨段**，避免破坏 run 结构与编号。
4. **分两档，明确选边**（这是关键判断）：
   - `--docx-inplace`（保格式档）：只做词级/短语级替换，**跳过切句、句序、段落重排**，
     保 run 结构 100%，但去味强度接近最低档。
   - 默认（纯文本往返档）：放开全引擎能力，UI 明确警告「样式会掉」。
   - 「既保格式又做结构级改写」在 run 结构上不成立，不要承诺。
5. **验收**：把 [format-fidelity-2026-10-26.md](format-fidelity-2026-10-26.md) 的 23 条不变式
   扩到 docx DOM 层；造一份含表格/图片/公式/批注/修订/页眉页脚的样例，
   比对解包前后**除 `<w:t>` 外的每个 ZIP 条目逐字节一致**。
6. **排期**：v0.9.89+ 独立立项。先做「只读体检」（能否准确识别不可改区域），
   再动写入；先 CLI，再 Web/桌面 UI。

### 2.3 不做

pptx / pdf（不同格式，另立项）、按检测报告定位段落（依赖第三方报告格式且踩 bypass 口径）、
翻译链、更长的词表、简繁转换 —— 沿用 [竞品对比-2026-10-27.md](竞品对比-2026-10-27.md) §5「不做」。
