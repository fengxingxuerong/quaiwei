# A/B 配对能力验收 · 首跑（2026-11-07）

## 这是什么

新增 `scripts/eval-dual/ab_accept.py`：用「哪段更像 AI」的强制选择裁决**两臂产物**，
替代 `aiScore` 做引擎改动的验收。

动机：`aiScore` 与独立评委只有 **0.353** 相关，且构成上奖励短句——三次切句收敛尝试
（切点守卫 / 单入口预算 / 四入口形态系数）全被它判成「更像机器」而回退，
见 [`../split-scale-2026-11-07/`](../split-scale-2026-11-07/)。

与 `eval_dual.py` 的分工：那边固定 orig vs local09（评「有没有效果」），
这边任意两臂（评「这次改动是不是更好」）。

## 本次被测改动：已上线的破折号修复 `9013ff3`

| 臂 | 内容 |
|---|---|
| A | `relaxEmDash` 候选 `["，", "。", "——"]`（修复前，破折号会被随机换成句号） |
| B | `["，", "，", "——"]`（修复后，破折号只换逗号或保留） |

两臂各 23 篇、均 5,451 字（标点替换不改字数）；语料 `scripts/realcase/cases.json`，
引擎 `intensity 0.6` / `seed 20260905`，同一份 `dist-cli` 分两次构建产出。

## 结果：测不出差异

| 口径 | 票数 | B 臂被选「更像人」 | 胜率 | 双席一致 | 甲被选率 | p（单尾） |
|---|---:|---:|---:|---:|---:|---:|
| 单席 | 23 | 11 | 0.478 | — | **0.826** | 0.66 |
| **镜像双席** | **46** | **21** | **0.457** | **0.348** | 0.696 | **0.77** |

镜像双席两席分别 10/23、11/23（彼此接近），但**第 47 票以后没有差异**。

## 四条结论

1. **该修复在「像不像 AI」维度无可测收益**：0.457、p=0.77，既没变好也没变差。
   这与它的定位一致——它是**语义正确性修复**（句内标点不该变句末标点），
   不是能力提升。别把它写进任何能力宣传。
2. **单席配对不可用**：甲被选率 **0.826**，评委强烈偏好第一段。
   这正是 `eval_dual.py` 双席反序设计的理由；单席数字只能作废。
3. **两臂差异过小时，配对接近噪声**：双席一致率仅 **0.348**（11-06 双网关同口径是 0.826）。
   本改动 23 篇里只有少数篇含破折号，多数篇两臂**逐字相同**，评委在被要求二选一时只能瞎猜——
   一致率低是预期的，也是工具的边界：**它测不出微小改动**。
4. **镜像双席 ≠ 真双席**：同模型同网关、只靠呈现顺序取反，甲被选率仍 0.696（真双席基线 0.500）。
   要用于「能力是否提升」的正式裁决，仍需两个独立网关 + 跨批次复测。

## 第二次裁决：切句收敛（实验阈值，30 票）

### 为什么这次要换语料与阈值

真实实现按 1000/6000 字收敛，而 realcase 23 篇最长 453 字 ⇒ 用默认阈值两臂产物
只有 **1/23 篇**不同，配对必然退化成瞎猜。所以本次：
- 阈值改按 **200/600 字**（实验版，非最终实现）；
- 语料换成 **15 篇真人维基长文各截前 2500 字**；
- 两臂 **15/15 篇全不同**，A 臂比 B 臂多 **70 个句号**（每千字约 1.9 个）。

### 结果

| 票数 | B 臂胜率 | 双席一致 | 甲被选率 | p（单尾） |
|---:|---:|---:|---:|---:|
| 30 | **0.433** | **0.533** | 0.267 | 0.82 |

逐篇：A 胜 5、B 胜 3、**两席完全相反 7/15**；票数分布 0/2 五篇、1/2 七篇、2/2 三篇。

### 结论

1. **测不出差异，方向还略偏「更差」**（0.433 < 0.5，p=0.82）。切句收敛在配对盲测里
   既没有得到支持，也没有被证伪。
2. **长文本配对判断极不稳定**：双席一致率 0.533 接近抛硬币，15 篇里 7 篇两席完全相反。
   30 票不足以裁决这种幅度的改动。
3. **顺序效应不稳定**：两次实验甲被选率一次 0.696、一次 0.267（偏向完全相反）。
   ⇒ 单次镜像双席不足以抵消位置/顺序效应，之前把单席 0.826 全归因于「位置偏置」
   也是过度解释。
4. ⇒ **当前唯一可用的评委 `qodercn/dfmodel` 在长文本上不足以裁决细微改动。**

### 下一步（三选一，成本递增）

| 选项 | 做法 | 代价 |
|---|---|---|
| a | 换更强/更稳的评委（如 `glm-5.3-flash`，需第二个网关） | 需凭证 |
| b | 加票数 + 多批次（每篇多席、隔日复测） | 30 票 → 90+ 票，约 1 小时 |
| c | 只裁决**大改动**，放弃细微改动裁决 | 承认工具边界 |

在选之前，**切句收敛维持回退**——没有证据支持保留，也没有证据支持永久放弃。

## 对下一步的意义

用它裁决 `splitScale`（切句收敛 −13%）是可行的：那里两臂在**每一篇**都不同，
一致率不会塌到 0.348。但仍要：
- 至少镜像双席（单席 0.826 的位置偏置不可接受）；
- 跨批次复测（11-06 已证同文隔日漂移 MAE 14.7，配对胜率必须复现）；
- 判定用「B 胜率显著 > 0.5（p<0.05）」，不显著就只能写「测不出」。

## 复现

```bash

node dist-cli/humanize-cli.mjs <23 篇目录> --out arms/b --intensity 0.6 --suffix .humanized
#   把 relaxEmDash 候选改回 ["，","。","——"]、build:cli，再跑一次到 arms/a，然后 git checkout 恢复

# 2. 验收（单网关用 --mirror；有第二个网关就去掉 --mirror 配 --url-b）

  --arm-a arms/a --arm-b arms/b --out out-mirror \
  --mirror --model qodercn/dfmodel --url-a http://127.0.0.1:8326

# 3. 离线复算
python scripts/eval-dual/ab_accept.py --summarize \
  --results evidence/ab-accept-2026-11-07/ab_results.jsonl --out verify
```
