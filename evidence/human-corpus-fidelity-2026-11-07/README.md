## `collapseIssues` 命中怎么读

这个判据原本给 **LLM 深度改写**查「内容腰斩」。规则引擎的切句也会让它命中，
所以**单列、不混进保真失败**。但抽查后确认：**不是纯误报，是真碎句化**。

| 原文 | 产出 |
|---|---|
| 鲁迅首创了以论理为主，形式灵活的新文体——"杂文"，并将之发扬光大 | 鲁迅首创了以论理为主。**形式灵活的新文体**，"杂文"，并将之发扬光大 |
| 他始终没有研究清楚……正因为这样，有些学者往往抓住… | 他始终没有研究清楚。**正因为这样。**有些学者往往抓住… |
| 諸葛亮一生"鞠躬盡瘁、死而後已"，是中国传统文化忠臣… | 引号内容保留完好（该篇命中的是别处） |

第一例产出「形式灵活的新文体」成了无谓语的悬空片段；第二例「正因为这样。」成了光杆连接词句。
两处都是**破折号 / 省略号被当作切点**造成的，不是事实丢失。

⇒ 与 [`docs/十篇小说测试报告-2026-10-28.md`](../../docs/十篇小说测试报告-2026-10-28.md)
的「本地引擎几乎不改词，改的是句子——每千字句数 +29%、50% 的句子被重切」同向。
已在 [SCORECARD 第 3 节](../../SCORECARD.md) 登记为**已知失败（未修）**。

## 为什么没写死成门禁

1. 语料未入库，CI 里跑不到；把依赖本地文件的测试接进 `npm test` 会红。
2. 项目约定「红测试绝不能留在仓库里」——缺陷先登记，修完再改成守卫用例。
3. `collapseIssues` 对规则引擎切句是**跨口径**判据，直接当失败会让门禁误报，
   反而训练人忽略红灯（项目已吃过 `check:regex` 193 次误报的亏）。
4. 「该不该改」没有人工标签，本探针不冒充这个判定。

## 这条发现对「能力提升」的意义

它比「继续加词表规则」更有指向性：**当前引擎对真人书面长文的主要伤害在切句边界**
（破折号、省略号、插入语），而不是换词。修切点守卫要在
`fragmentCanStand` / `findSplitPoint` 层动，并会牵动 12 样本棘轮与
`sweep:format` 4080 次不变式——**属于要单独评估的一轮，不在本轮改动范围内**。

对照参考：2026-11-04 路线图曾建议把「句长节奏 CV」做成显式优化目标，
但 `src/engine/shuffle/burstiness.ts:408` 已记录 v0.9.6 实测 CV 判别力≈0 且方向反、
反向项被删除。别为了「让句子更不整齐」再加切句。
