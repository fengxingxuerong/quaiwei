### 顺带抓到一个真缺陷（已修）

MCP 的 `humanize_text` 不传 seed 时，引擎的 `makeRng(seed)` 退回 `Date.now()`，
同一段 114 字在三个进程里跑出 **101 / 106 / 101 字**三种结果——"固定 seed 可复现"成了空话。

修法：MCP 侧显式给默认种子 20260905（与 CLI `--seed` 一致）。修后同一输入跑 4 个进程：

```
run 1 len 106 score 14
run 2 len 106 score 14
run 3 len 106 score 14
run 4 len 106 score 14
```

守卫用例：`不传 seed 时落的是文档里的默认种子`（这条在修之前是红的）。

### 探测：这个门有多难被触发

10 类学术片段（`\cite`/`\ref`/上下标/全角数字/区间/单位/列表/公式）× 3 文风 × 2 强度 × 3 种子
= **180 组，阻断项 0 条**。结论写进 docs/academic-check.md 第 4 节：守卫确实守住了，
但这条门在当前路径上很少响——它的价值是"以后改坏了会响"。

未验证到：退出码 2 的**端到端**路径。阻断逻辑由单元测试覆盖，但因为本地引擎在这 180 组里
一次阻断项都没产出，CLI 级只验到 READY=0 与"没法跑"=1。这条已写进文档「已知没做的」。

**第二轮补上了**（`--against`，审外部改写稿）：

```
node dist-cli/humanize-cli.mjs paper.md --academic-check --against bad.md
exit=2
✗ NOT READY：5 个阻断项（退出码 2）

- 产出缺少原文中的数字：4.2个百分点、91.2%
- 结构：表格分隔行不丢 —— 原文 1 条 → 产出 0 条
- 结构：表格行列数守恒 —— 表头+数据行 原文 2 → 产出 0
- 结构：表格行连续段守恒 —— 原文段长 [3] → 产出 []
- 引用键丢失（\cite）：wang2024

# 换成只动措辞、数字引用都留着的改写稿：
node dist-cli/humanize-cli.mjs paper.md --academic-check --against good.md
exit=0
✅ READY：机器没看见阻断项（退出码 0）
```

### 浏览器里顺带核到的一件事

提示里写着「多候选择优：8 稿中挑最优（淘汰 0 稿，中选种子 2020967955）」——
`humanize-bestof.ts` 的 `base = opts.seed ?? Date.now()`，而网页版不传 seed。
所以**网页版每次跑出来的结果不完全一样**，它把中选种子报出来供回填（CLI/MCP 则默认固定种子）。
这是既有设计，不是本轮引入的缺陷；已写进 SCORECARD 第 1 节，免得"确定性"这句被误读成网页版也稳定。

### 一次自伤与修复（留个记录）
