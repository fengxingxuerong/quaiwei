# 优化实验（判据类，均未上线）· 2026-11-21

> 针对外部数据集发现的两个负面问题（aiScore 长文判反、改写靠碎句骗分），做**受控实验**。
> 按项目纪律：**判据改动单独立项 + 双席 A/B**，双席通过前**绝不改产品默认**。
> 本轮只产出实验证据与决策建议，产品代码判据零改动（全量 2408 用例基线不变）。

## 一、实验 A：aiScore 的 avgLen 项候选修正

脚本 `scripts/avg-len-criterion-experiment.ts`，只替换 avgLen 一项，其余分项原样。
双集：自建语料（探索集，human 36 / AI 32）+ DetectRL-ZH dev（验证集，只读不调参）。

| 候选 | 自建(探索) 总体/长文 | DetectRL(验证) 总体/长文 |
|---|---|---|
| baseline（长句=AI） | 0.719 / 0.583 | 0.575 / 0.485 |
| norm（句长+均匀度） | 0.721 / 0.585 | 0.615 / 0.525 |
| capped（长文减半） | 0.681 / 0.571 | 0.585 / 0.540 |
| **inverted（短句=AI）** | 0.679 / 0.541 | **0.746 / 0.737** |

**结论：不上线。** inverted 在 DetectRL 上大幅提升（0.575→0.746），但在自建语料上
下降（0.719→0.679）——**两集机写文本的句长特征方向相反**：
- DetectRL（GPT-4o/GLM/Qwen 生成）机写偏碎句 → 短句=AI 成立；
- 自建语料（本地引擎/GLM 臂）机写偏长句 → 长句=AI 成立。

⇒ 单一 avgLen 方向无法通用判 AI。调方向是数据集过拟合，不改产品默认。

## 二、实验 B：碎句化骗分约束

脚本 `scripts/fragment-guard-experiment.ts`：对 DetectRL machine 样本 300 篇 × 3 seed，
限制改写后句数增幅（碎句化代理），看降分与可分性 AUC（越接近 0.5 越人机难分）。

| 句数增幅上限 | 覆盖率 | 改写后 AUC | 均分变化 |
|---|---:|---:|---:|
| 无约束 | 100% | 0.2645（判反） | -13.79 |
| **≤50%** | 48.3% | **0.5196** | -3.99 |
| ≤25% | 12% | 0.6009 | -0.56 |
| ≤10% | 1.3% | 0.6111 | -0.14 |
| ≤0%（不改） | 0 | 0.6143 | 0 |

**结论：候选有真实价值，但须双席 A/B 后才考虑上线。** 无约束改写把 AUC 从 0.614
砸到 0.2645（判反=骗分）；而句数增幅 ≤50% 的克制改写，AUC≈**0.52（几乎完美人机难分）**，
同时仍降分 -3.99。这证明**限制碎句能让改写更接近真人，而非骗分**。

但两个前置条件未满足，故本轮不上线：
1. **覆盖率仅 48%**：需"多候选挑稿"机制（项目已有 `contestSamples` 思路）才能让多数篇受益；
2. **必须双席 A/B**：AUC 是 aiScore 口径（自评分），不是独立评委。需按项目纪律用
   `ab_accept.py` 双席盲测验证"克制改写"是否真被评委判更像人，且**不与碎句化率指标一起调**
   （历史上切句收敛两次被双席判退化，见 `evidence/split-scale-2026-11-07/`）。
