# 碎句约束（split budget）可行性：不做引擎改动先拿判据（2026-11-26）

## 一句话

把引擎多切出来的句号**精确还原**成原文的逗号（只动「。」↔「，」，两臂逐字节校验），交给异源双席评委配对选择，**拿不到「限制切句更像人」的独立证据**：拆席后两席各自都是 artifact——DeepSeek 的票跟着「更接近原文」走（人写组 20.0% / AI 组 63.6%，差 43.6pp），Bailu 无差别偏好长句版（两组 12.5% / 7.7%）。
⇒ **不实现 `splitBudget` 引擎参数、不改默认切句行为**。这是该方向的第 4 次尝试，前三次（切点守卫 / `rhythm` 单入口预算 / 四入口 `splitScale`）都是失败或被回退。

## 为什么先做离线实验而不是直接写参数

待办里这条卡着三个前置：真参数、有区分度语料、双席 A/B。「事后精确还原」能构造出**与真预算等价**的产出（切句只把逗号换成句号，还原就是逆操作），所以先用它拿判据，再决定要不要动核心管线（真预算要改 4 个切句入口 + `humanize()` 主链，至少 7 个文件）。

## 第一步：碎句化到底有多严重（基线）

`probe.ts`，`humanize()` intensity 0.9 / seed 20261015，口径 = 输出句数 ÷ 输入句数。

| 语料 | n | 切句倍数中位 | 均值 | 最大 | 输入 avgLen → 输出 | 句/千字 |
|---|---|---|---|---|---|---|
| realcase 23 篇（AI 风格短稿） | 23 | **1.20** | 1.23 | 1.86 | 36.3 → 26.4 | 26.2 → 32.6 |
| 人写长文（human-corpus） | 12 | **1.80** | 1.73 | 1.98 | 39.7 → 22.8 | 21.8 → 41.2 |

关键相关性：人写长文 `corr(输入句长, 切句倍数) = 0.734`、`corr(字数, 倍数) = -0.011`
⇒ **碎句化不是「无差别撒碎句」，它跟着输入句长走**：原句越长切得越多，短句 AI 稿几乎不动（中位 1.20）。
预算 1.2 的影响面：realcase 9/23、人写长文 12/12。

完整数据 `split-ratio-baseline.json`；复现 `npx tsx evidence/split-budget-2026-11-26/probe.ts`。

## 第二步：A/B 设计（关键是两组偏置方向相反）

| 项 | 设置 |
|---|---|
| 臂 A（`arms-engine`） | `humanize()` 默认产出（intensity 0.9 / seed 20261015） |
| 臂 B（`arms-capped`） | 同文本，把「原文该位置本来是逗号」的句号还原成逗号，直到句数 ≤ 输入 × 1.2 |
| 还原判据 | `norm(前句) + "，" + norm(后句)` 是 `norm(原文)` 的子串 ⇒ 该边界原本必是逗号（切句只换标点，不改字） |
| 合并顺序 | 全局最短前句优先（先收碎句，不焊长句）；逐行处理，换行符一个不动 |
| 语料 H 组 | `artifacts/human-corpus` 400~12000 字，16 篇全合格；1.90 → 1.45 |
| 语料 A 组 | `scripts/realcase` 高比值 2 篇 + `detectrl-zh-dev.json` label=1 长样本（seed 20261126）11 篇；1.40 → 1.27 |
| 合格线 | 还原 ≥3 处且原比值 ≥1.3（否则两臂差异太小，等于让评委掷硬币） |
| 评委 | A 席 `deepseek-v4.1-flash-1017`（discovery-api）、B 席 `bailu-2.8`（bailucode） |
| 协议 | STRICT 纯 JSON `{"pick":"甲/乙"}`，`max_tokens 512` / `temp 0.6`，问「哪段更像 AI 生成」，位置翻转抵消偏置 |
| 票数 | 29 对 × 2 席 = 58 票，**干净票 50**，0 网络错，8 票格式失败（全是 A 席，见下） |

**为什么必须两组**：还原版天然更接近它的原文——H 组原文是人写的 ⇒ 偏袒受限版；A 组原文是机器写的 ⇒ 偏袒引擎版。
**只有两席、两组都朝同一方向，才算「限制切句」本身有效，而不是「更像原文」效应。**

两臂唯一差异已逐对校验：去掉全部「。」「，」后两侧字符串完全相同、长度相同（29/29 通过）⇒ 没有夹带别的改动。

## 结果

| 组 | 受限版被判「更像 AI」 | p（精确二项） | 两席都说受限版更像 AI | 两席都说引擎版更像 AI | 席位异质性 |
|---|---|---|---|---|---|
| H（人写，偏袒受限版） | **4/26 = 15.4%** | 5.3e-4 | 0/16 | 6/16 | 2/10 vs 2/16，Fisher p=0.63 |
| A（AI 稿，偏袒引擎版） | **8/24 = 33.3%** | 0.152 | 1/13 | 4/13 | **7/11 vs 1/13，Fisher p=0.0078** |
| 合并（不可定论） | 12/50 = 24.0% | 3.1e-4 | 1/29 | 10/29 | A 9/21 vs B 3/29，p=0.017 |

逐对明细见 `analyze.txt`。

### 拆席（决定性的那张表）

| 席位 | H 组（偏袒受限版） | A 组（偏袒引擎版） | 差值 | 读法 |
|---|---|---|---|---|
| A 席 DeepSeek | 2/10 = **20.0%** | 7/11 = **63.6%** | **+43.6pp** | 票跟着「更接近原文」走，H 偏受限、A 偏引擎 |
| B 席 Bailu | 2/16 = **12.5%** | 1/13 = **7.7%** | −4.8pp | 两组都压倒性偏好受限版，与原文无关 |

- **DeepSeek 的 43.6pp 落差正是 proximity bias 的签名**：它不是在判断「切句好不好」，是在判断「哪段更像它见过的那份原文」。
- **Bailu 29 票里只有 3 票选受限版更像 AI（10%）**，等于无差别偏好长句版（该席在 11-26 的 50 对扩样里已知偏弱：16/50）。

## 怎么读（以及为什么不能写成「同向」）

1. **H 组不能当证据**：15.4% 与「还原版 = 回到人写原文」这个混淆完全一致。
2. **A 组是决策相关的那组，但它两席对立且显著**（Fisher p=0.0078）⇒ 方向不一致，按项目口径不能当通过判据。
3. **A 组功效不足**：要检出真实 33%（相对 50%）在 80% 功效下需要 ≈ **66 票**，实际只有 24 票。33.3% 只能作方向性。
4. **8 张废票本身是信息**：全是 DeepSeek 在推理里写「两段几乎相同，只有标点差异」，然后纠结到不输出 JSON。差异**能被感知**，但没形成稳定判断——说明标点层面的差异对 LLM 评委不是可靠信号。
5. **与 2026-11-08 的强收敛 A/B 不是同向，这一点必须写清**：那轮是把句号密度整体收回原文（目标 ≤25/千字），90 票里收敛稿只赢 20 票 = **0.222**，判明确退化；而且那轮的偏置方向**不利于**收敛稿（原文都是真人长文，收敛稿更接近原文却仍然输）⇒ 在偏置逆风下仍输，更像真有信号。
   本轮是**弱还原**（上限 1.2 倍，中位只从 1.90 降到 1.45 / 1.40 降到 1.27），A 组方向相反但功效不足、且由弱席驱动。
   ⇒ 两条合起来的正确表述是：**强档（全密度收敛）明确退化，弱档（1.2 倍上限）方向不稳定且无独立信号；不存在任何一个能拿到双席一致增益的档位。**

## 结论（可引用口径）

- **不实现 `splitBudget` 引擎参数，不改默认切句行为。** 理由：没有任何一条是独立于「更像原文」的增益证据；决策相关的 A 组双席方向显著对立且功效不足。
- **碎句化的性质已澄清**：它由输入句长驱动（`corr=0.734`），短句 AI 稿接近不动（中位 1.20）。「引擎无差别撒碎句」不成立；拿「句号密度」当人味代理指标也是错的方向。
- 要给出定论，下一步必须是 **A 组扩到 ≥66 张干净票**；受合格对子数量限制（当前 13 对），得先找到切句倍数 ≥1.6 的 AI 语料，而不是继续在人写语料上加票。

## 局限

1. 受限版是**离线精确还原**，不是引擎内真预算：真预算会让下游 pass 看到不同的句数，产出可能不完全等价（差异仅限这些切点，未端到端验证）。
2. H 组存在结构性混淆（见「怎么读」1），不可用于定论。
3. A 组 13 对里 realcase 占 2 对，其余是 DetectRL 机器标注样本（中位约 800 字），体裁偏说明文。
4. 评委是 LLM 不是人；Bailu 席存在系统性长句偏好（已知弱席）。
5. 单强度（0.9）单 seed（20261015）。强度 0.7 切句量更低，结论是否外推未验。
6. 本轮**未动产品代码**，不宣称任何验收通过。

## 复现

```bash
# 1) 基线（约 1 分钟，只读语料）
npx tsx evidence/split-budget-2026-11-26/probe.ts

# 2) 组装两臂（--write 才落盘；输出到 D:/projects/_quaiwei-tmp/split-cap-ab-2026-11-26）
npx tsx evidence/split-budget-2026-11-26/prepare.ts --write

# 3) 配对裁决（异源双席，需要两把 key）
BASE=D:/projects/_quaiwei-tmp/split-cap-ab-2026-11-26 ARM_A=arms-engine ARM_B=arms-capped \
URL_A=https://discovery-api.intern-ai.org.cn/v1/chat/completions MODEL_A=deepseek-v4.1-flash-1017 KEY_A=... \
URL_B=https://bailucode.com/openapi/v1/chat/completions MODEL_B=bailu-2.8 KEY_B=... \
MAX_TOKENS=512 TEMPERATURE=0.6 STRICT=1 node scripts/ab-pair-judge.mjs

# 4) 统计
BASE=D:/projects/_quaiwei-tmp/split-cap-ab-2026-11-26 node evidence/split-budget-2026-11-26/analyze.mjs
```

文件：`split-ratio-baseline.json`（基线）· `prepare-report.txt`（逐篇 rBefore/rAfter）· `arms-engine/` `arms-capped/`（29 对两臂原文）· `results.jsonl`（58 票原始记录）· `analyze.txt`（统计输出）· `probe.ts` `prepare.ts` `analyze.mjs`（脚本）。
