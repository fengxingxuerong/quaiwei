# 按形态调切句强度：三次尝试与度量墙（2026-11-07）

用户选定「重构切句管线」后，本文件记录第三次尝试的完整结果。
**代码全部回退，仓库只增加证据**——原因见第四节。

## 一、这次做了什么

在 `humanize.ts` 引入 `splitScale`（切句收敛系数），按**文本长度 + 体裁**计算：

```
1000 字以内 → 1.0（12 样本最长 718 字、realcase 最长 453 字、V8_CORPUS 均短 ⇒ 逐字不变）
6000 字以上 → 0.45；中间线性插值
叙事 / 人写再乘 0.9（作者结构优先）
```

接到四个切分入口（此前实测确认的四个来源）：

| 入口 | 接法 |
|---|---|
| `sentence`（逐句劈长句） | `rng() < SPLIT_SENTENCE_RATE * intensity * splitScale` |
| `rhythm`（节奏兜底） | 每段刀数 `8 → round(8 × splitScale)` |
| `clamp`（句长钳制） | 目标句长 `avgLenTarget → +round((1−scale)×12)`；刀数同上 |
| `para`（段落重切） | `resegmentParagraphsAggressive(..., intensity × splitScale, ...)` |

`splitScale` 作为 `HumanizeOptions` 的内部字段传递，不暴露 CLI / MCP，不传 = 1 = 旧行为。

## 二、效果：−13%，不够

| 指标 | 改前 | 改后 |
|---|---:|---:|
| 21 篇真人维基新增句号 | 3,135 | **2,715** |
| **每千字新增句号** | **17.9** | **15.5（−13%）** |
| 明朝篇（27,267 字） | +572 | +498 |
| `collapseIssues` 命中 | 12/21 | 12/21 |
| 事实/格式保真 | 0 失败 | 0 失败 |

四个入口全接上，总量只降 13%。说明「新增句号」还有相当部分来自**未被识别为切分入口的路径**
（标点松弛、模板替换、合并后重切等），继续追需要逐阶段做句号计数探针，成本继续上升。

## 三、代价：12 样本棘轮真红

```
❌ N1 [叙事·基础档(0.6)] 降为优 ❌ 上升 4.8 → 5.2（更像机器了），违反「≤ 基线」
```

叙事档切句收敛后，`aiScore` **上升** 0.4。这不是噪声，是方向性的：改前 E/N1=4.8、改后 5.2。

## 四、为什么回退，以及真正的瓶颈

这是同一条路上的**第三次**尝试，三次都撞在同一堵墙：

| 次 | 做法 | 结果 |
|---|---|---|
| 1 | `findSplitPoint` / `findGuardedCutNear` 加破折号省略号守卫 | 完全无效（字数与命中数都不变） |
| 2 | `rhythm` 单入口加全文切句总预算 | 无效（18.0/千字） |
| 3 | 四入口统一 `splitScale`（按长度+形态） | −13%，但 `E/N1` 棘轮红 |

**共同根因不在引擎，在尺子**：`aiScore` 的构成里，句子越短、节奏越碎，分数越低（越「像人」）。
所以任何「少切句」的改动，方向上都表现为 aiScore 上升，必然被 12 样本棘轮拦下。

这正好复现了项目早就写下的结论：`aiScore` 只是「词表命中的套话/公式化表达」的代理指标，
与独立评委只有 **Pearson 0.353**（2026-11-06 双网关 23 篇）。

⇒ **在使用与目标一致的验收口径之前，切句收敛不可能通过门禁。**
用 `--rebaseline --accept-worse E/N1` 硬放行是错的：那不是「接受真退化」，
而是「承认尺子与目标冲突」，该改的是尺子，不是基线。

## 五、建议的下一步（顺序不能反）

1. **把双席配对盲测做成能力验收**：对「改前 vs 改后」做配对强制选择，
   而不是看 `aiScore`。已有 `scripts/eval-dual/`（参数化、`--seats`、`--summarize`），
   把它从「离线复核」扩展成「A/B 验收」，用 23 篇 × 2 席 ≈ 62 次调用即可判定。
2. 验收口径稳定后，再提交 `splitScale`，用配对胜率而不是 aiScore 判定是否保留。
3. `12 样本棘轮` 继续守 `aiScore`（它守的是「词表去味能力没退化」），但不作为切句强度的裁判。
