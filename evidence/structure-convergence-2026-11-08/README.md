# 按结构目标重做切句收敛（2026-11-08）

**结论先行（两把尺子给出了相反结论）**：按 `--metrics` 的结构目标，第四次切句收敛
第一次达标——15 篇真人长文句号密度 **37.35 → 24.26/千字**（目标 ≤25）、句长 23.78 → 34.98、
逗号/句 0.51 → 1.21，只改标点、保真 0/15 失败、全套门禁零回归。
但双席异源配对裁决里，收敛稿 **只赢 8/30 票 = 0.267**（双席一致 0.733）：
评委明显更偏好碎句版。按项目 2026-11-07 定下的「能力验收必须双席配对」口径，
这属于能力退化 ⇒ **不推成默认行为**，`humanize()` 只在显式 `opts.convergence: true` 时调用。

本轮交付的是「一把可复算的结构尺 + 一份阴性裁决 + 一个可复现的实验开关」，
**不是一次默认行为变更**。

## 一、为什么前三次失败：尺子不对，落点也不对

`aiScore` 与引擎共用词表且构成上奖励短句，任何「少切句」的改动都会被它判成
「更像机器」。三次尝试（切点守卫 / rhythm 单入口预算 / 四入口 `splitScale`）
全部撞在这堵墙上：四入口全接上只把新增句号降 13%，还让 `E/N1` 棘轮 4.8→5.2。
细节见 [`../split-scale-2026-11-07/`](../split-scale-2026-11-07/)。

本轮先做**逐阶段句号计数诊断**：临时在 `emitStage` 插一行 `DIAG_P` 计数（已回退，
`src/` 与插桩前逐字相同），用 15 篇真人维基各截前 2500 字、
`intensity 0.6` / `seed 20260905` 跑主路径，按阶段 id 聚合：

| 阶段 | 句号数（15 篇均值） | Δ |
|---|---:|---:|
| 输入 | 50.8 | — |
| `genre` | 50.8 | 0 |
| `para` | 58.5 | **+7.7** |
| `zhuque` / `structure` / `dedupe` | 58.5 | 0 |
| `rhythm` | 74.9 | **+16.4** |
| `derivs` / `antifp` | 74.9 | 0 |
| `clamp` | 88.6 | **+13.7** |
| `burst` | 91.7 | **+3.1** |
| `final` | 91.7 | 0 |

四个增量来源各自按「句长均值 / CV 达标」循环到满足为止，**压刀数上限不等于压句号数**；
`clamp` 与 `limitPunctuation("……",1,"。")` 无条件生效；`para` 段内的
`splitOnConnectors` / `burst-single` 根本没被 `splitScale` 接到。
结论：继续在源头调预算是死路，改成**对最终产出的目标值直接收敛**。

同时量了「原文句读可识别性」：15 篇产出共 1375 个句末标点，
用「原文每处句读前后 5 字」做锚命中 689（50.1%），疑似引擎新增 668 个，
达标只需还原 449 个 ⇒ 候选充足，后处理方案可行。

## 二、方案：只改标点，把引擎造出来的句号还回去

新增 [`src/engine/structure-convergence.ts`](../../src/engine/structure-convergence.ts)，
可在 `humanize()` 的 `final` 之后调用（**默认关**，`opts.convergence: true` 才启用；
不暴露 CLI / MCP 参数）。下面所有验收都是「显式开启」的 B 臂对照「产品默认」的 A 臂。

| 判据 | 做法 | 为什么 |
|---|---|---|
| 目标 | `max(原文密度, min(25/千字, 原文密度 + 4.4/千字))` | 原文密度高的稿子（红楼梦 ≈29.6/千字）不能为了凑 25 而改掉原文句号 |
| 原文保护 | 原文每处句读的「前 5 字 / 后 5 字」进锚集合，产出里命中任一锚的句号不动 | 宁可少还原，不可误还原原文句读 |
| 形态守卫 | 只还原**段内** `。`；不动 `！？`、不跨段、跳过代码块 / 表格行 / URL 段、不还原后接引号的句号、合并后 >72 字不还原 | 不破坏结构与格式 |
| 确定性 | 按「前句 + 后句字数」升序、同分按位置升序取前 N 个 | 同输入同输出，不调 rng / 模型 / 网络 |
| 短文本 | 原文去空白 <1000 字时逐字返回 | 12 样本最长 718 字、realcase 最长 453 字 ⇒ 棘轮与既有基线不受影响 |

「只改标点」让「不新增事实」在构造上继续成立：去标点后，收敛前后逐字相同。

| 篇目 | 收敛后句号/千字 | 原因 |
|---|---:|---|
| 科技-物理-量子力学 | 25.86（目标 25.04） | 候选 32/32 全部用尽；保守判据下无法再降，属**部分达标** |
| 文学-古典-红楼梦 | 30.02 | 原文密度 ≈29.6/千字，`max(原文密度, …)` 目标下限保护，设计内 |

其它边界：
- **默认关闭**：产品行为与改动前逐字相同；所有能力数字、README 宣传、SCORECARD 基线均不变。
- 短文本（<1000 字）完全不收敛，碎句化在长文上才显著；这是刻意的棘轮保护。
- 只处理 `。`，`！？` 数量本身就超目标的文本会停在「候选耗尽」。
- 锚是启发式：词表替换可能让原文句读漏命中，故额外叠加「段内 / 形态 / 合并长度」守卫。

## 五、双席配对结果：两把尺子冲突

| 口径 | 数值 |
|---|---:|
| 票数 | 30（15 篇 × 2 席） |
| 收敛稿（B 臂）被选「更像人」 | **8 票 = 0.267** |
| 分席 | A 席 3/15、B 席 5/15（**两席同向**） |
| 双席一致率 | **0.733** |
| 甲被选率 | 0.367 |
| p（单尾，B 胜） | 0.997 |
| 错误 | 0 |

**这不是噪声**：11-07 四次 A/B 都「测不出」时双席一致只有 0.348~0.533；
这次两臂差异足够大（句号 −35%），一致率 0.733，两席同向判 A 臂（碎句版）更像人。
即「A/B 测不出」的边界被越过后，评委第一次给出了清晰、可复现的反方向裁决。

**为什么冲突**：11-06 的 87% 配对基线本来就是「改写稿（碎句）比原文更像人」，
说明 LLM 评委把短句 / 碎节奏当成人味信号；而真人维基原文的句号密度只有 20.63/千字。
把产出拉回真人句法结构，反而偏离了评委的「像人」判据。
⇒ **结构仿真度与评委偏好是两件事，不能互相代替**；`--metrics` 能回答「结构变了多少」，
不能回答「变好没有」。

**处置**：按既有验收口径判退化，默认关闭。未做跨批次复测（单批 13 分钟），
按规范单批结果不作最终能力结论，因此也**没有把「收敛无用」写死**。
后续三条路：① 跨批次复测确认方向；② 换目标（不追真人密度，只压最极端的碎句）；
③ 放弃方向，保留这把尺子作诊断工具。

**没跑的**：`eval_dual.py` 的「改后稿 vs 原文」87% 基线回归未重跑
（本轮产品默认未变，理论上不受影响）；跨批次复测未做。
