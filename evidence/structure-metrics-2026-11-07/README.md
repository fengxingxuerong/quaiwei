# 结构指标尺子（`--metrics`）首跑（2026-11-07）

## 为什么造第三把尺子

| 尺子 | 问题 |
|---|---|
| `aiScore` / `detectAI` | 与引擎共用同一份词表 ⇒ 改写后下降是构造性保证（与独立评委 Pearson 0.353） |
| 配对盲测（`ab_accept.py`） | 长文本 + 细微改动下四次都测不出：0.478 / 0.457 / 0.433 / 0.517，双席一致 0.348~0.533 |

新增 `src/engine/structure-metrics.ts` + CLI `--metrics`：**纯句法统计**，
不碰词表、不调模型、不用随机数，同输入同输出。它不判断「像不像 AI」，
只回答「这次改动让句子结构变了多少」。

## 首跑：引擎对真人长文做了什么

语料：15 篇真人维基长文各截前 2500 字（`split-run/corpus`），默认档
（`intensity 0.6` / `seed 20260905`）。A 臂 = 当前引擎，B 臂 = 切句收敛实验版。

| 组 | 句号/千字 | 句长均值 | 句长 CV | 短句% | 逗号/句 | 每段句数 |
|---|---:|---:|---:|---:|---:|---:|
| **原文（真人）** | **20.63** | **41.17** | 0.62 | 3.0 | **1.49** | 4.41 |
| A 臂（当前引擎） | **37.35** | **23.78** | 0.56 | 6.0 | **0.51** | 5.50 |
| B 臂（切句收敛） | 35.44 | 24.96 | 0.55 | 5.0 | 0.58 | 5.74 |

## 三条结论

1. **碎句化的本质是「把复句拆成单句」，不是单纯切短。**
   句号密度 +81%（20.6→37.4）、句长 −42%（41.2→23.8）、
   **逗号/句 −66%（1.49→0.51）**、段内句数 +25%。中文的流水句被拆成一串短句，
   这正是「换词不换骨」之外的第二个结构级改动，此前从未被量化过。
2. **切句收敛的幅度远远不够。** B 臂只把句号密度从 37.35 压到 35.44（−5%），
   离原文 20.63 还差 **−42%** 的量级。这解释了为什么配对盲测测不出：
   两臂差 5%，评委在 2500 字长文里几乎感知不到。
3. **这把尺子能裁决 A/B 测不出的改动。** 同一对产物，配对盲测给 0.433（p=0.82），
   结构指标给出「句号 −5.1%、逗号 +13.7%、短句 −1pp」——可复算、可 diff、不需要评委。

## 对「要不要继续救切句」的判断

要救就按结构目标救，而不是按 `aiScore`：
- 目标区间取原文分布（句号 20.6/千字、句长 41 字、逗号 1.49/句）；
- 当前 37.35 → 目标 ≤25，需要 **−33% 以上**的切句收敛，是 B 臂（−5%）的 6 倍；
- 这种幅度必然显著改变去味产出，需要重新评估守卫与 12 样本棘轮——
  但它至少是**有明确目标**的改动，而不是「凭感觉少切一点」。

## 复现

```bash
# 单份
node dist-cli/humanize-cli.mjs 稿.txt --metrics

# 整目录（加 --suffix 占位以关闭「跳过已改写文件」）
node dist-cli/humanize-cli.mjs arms/long-a --metrics --suffix .__none__

# 直接给 delta
node dist-cli/humanize-cli.mjs 原稿.txt --metrics --against 改后稿.txt
```

单测：`npm test -- src/engine/structure-metrics.test.ts`（10 例，钉住纯函数性、
句长分位关系、逗号只认全角、空串边界、delta 排序与 0 基线给 null）。
